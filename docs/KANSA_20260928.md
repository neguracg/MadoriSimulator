## 2. データ保全

- 保存は localStorage のみ。保存失敗は `catch { /* ignore */ }` で握りつぶされ、利用者に伝わらない。
- 読み込みに失敗すると既定の空プロジェクトで起動し、次の自動保存が壊れた元データを上書きする（退避なし）。
- 全間取りをまとめて書き出す手段が無い（エクスポートは表示中の1件だけ）。

## 4. 設計方針（着手前5問の答え）

1. 同じ知識を持つ場所
   - 文書の妥当性検査が3箇所 → `src/state/migrate.ts` の `normalizeDoc()` へ集約
   - 「部屋の移動に連動する開口部・家具」の判定が Canvas.tsx と docOps.translateRoom の2箇所 → 1関数へ集約し両方から呼ぶ
   - マスの所有者マップ（z 順）が Canvas と docOps の2箇所 → geometry へ
   - 数値の自由入力が FurniturePanel にだけ実装 → `NumberField` 部品にして設定・ドア幅でも使う
2. 同種の既存機能
   - ドラッグ確定の3箇所（辺/角・ドア/窓・家具）を同じコミットで直す。ライブ値は ref に持ち、pointerup のハンドラから直接確定する
   - 間取りを増やす経路（新規・共有リンク取込・複製・ファイル読込・別タブ統合）は1つの追加関数を通す
   - 文書を離れる経路（モード切替・階切替・タブ切替・新規・取込）は重なり解決を同期で済ませてから保存する
3. 引っ越し: 保存・読込を App.tsx から `src/state/projectStore.ts` へ移す。保存キー `madori-simulator-project-v1` と旧キー `madori-simulator-doc-v1` からの移行は維持する
4. 過去の類似改修: de0c5bf（家具の自由入力）・84bf2f9（移動への追随）。WORKLOG / BUGLOG は未作成
5. 所有モジュール: 文書の正規化=migrate.ts／永続化=projectStore.ts／開口部と壁の対応=新規 `src/state/openingOps.ts`／履歴=useHistory.ts

その他の決定:
- 貼り付けた部屋は形を保ったままグリッド内へずらし、貼付後は移動モードへ切り替える（重なりは従来どおり編集へ戻る時に解決）
- 部屋の移動は個別のマスではなく移動量をクランプする。プレビューも同じ関数を使う
- ローカル起動中の共有リンクは公開版 `https://neguracg.github.io/MadoriSimulator/` を基底にする
- 起動時に、移行・書き込みの前の生データを別キーへ退避する
- テストは vitest（純ロジック）と、ビルド済みを自前で起動して操作する Playwright スクリプト（dev / 本番ビルドの両方）
